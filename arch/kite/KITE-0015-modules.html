1. Область применения

Документ определяет модульную систему Kumir 3: формы импорта, порядок резолюции пути, регистрацию импортированных имён, пространства имён и доступ к членам модуля, объявление модуль … кон, инструкцию экспорт, состав манифеста проекта kumir.toml, а также кэширование модулей и обнаружение циклов.

Документ не решает следующих вопросов:

  • каталог встроенных библиотек, их API и версии — в KITE 5;
  • форма записи импортов и операторов . и :: — в KITE 12;
  • устройство окружений, в которые попадают импортированные имена, — в KITE 4;
  • издания языка и режим совместимости — в KITE 6;
  • вычисление выражений доступа к члену — в KITE 13.

2. Термины и обозначения

Модуль — единица кода, из которой другой код берёт алгоритмы и классы. Файловый модуль — отдельный файл .kum. Модуль-проект — директория с манифестом kumir.toml. Именованный модуль — блок модуль … кон внутри файла. Библиотека — модуль, загружаемый по имени из реестра библиотек либо из директории или файла как библиотека. Резолвер — процедура, определяющая вид импорта по форме пути. Базовая директория — каталог, относительно которого разрешаются относительные пути. Пространство имён модуля — префикс полного имени, отделённый точкой (Алиас.имя).

Ключевые слова требований — ДОЛЖЕН, НЕ ДОЛЖЕН, СЛЕДУЕТ, МОЖЕТ — применяются в значении KITE 0 § 2.2. Метки стабильности — по KITE 0 § 5; метка стоит в строке таблицы или в конце пункта и в тексте не повторяется.

3. Нормативные правила

3.1. Виды модулей

Модулем является:

  • отдельный файл .kum — файловый модуль;
  • директория с манифестом kumir.toml — модуль-проект;
  • встроенная библиотека (время, система, файлы, сеть);
  • пользовательская библиотека — директория или файл, загружаемые как библиотека;
  • именованный блок модуль … кон внутри одного файла.

Все формы вводятся двумя взаимозаменяемыми ключевыми словами — использовать и подключить. Семантически они не различаются: вид импорта определяет резолвер по форме пути, а не по ключевому слову (§ 3.3).

3.2. Формы импорта

использовать <путь> [: имя1, имя2, …] [как Алиас]
подключить  <путь> [: имя1, имя2, …] [как Алиас]

Путь записывается строковым литералом ("./математика.kum") или идентификатором (время, сеть); обе записи допустимы.

ПримерЧто импортируетсяСтабильность

использовать время как тБиблиотека под алиасом т.стабильно
использовать время@^2.0Библиотека с указанием версии (SemVer, только для библиотек).экспериментально
подключить "./математика.kum"Соседний файл .kum по относительному пути.стабильно
подключить "./математика.kum" как матФайловый модуль под алиасом мат.стабильно
подключить "../общее/утилиты"Файл без расширения; резолвер добавляет .kum.стабильно

Разделитель списка выборочного импорта — двоеточие Список имён выборочного импорта ДОЛЖЕН записываться после двоеточия: использовать Модуль: имя1, имя2. Запись с фигурными скобками (использовать время { … }) грамматике языка не принадлежит.

3.3. Порядок резолюции импорта

Резолвер проверяет форму пути в строго фиксированном порядке и применяет первое сработавшее правило:

№ПроверкаДействие
1 Директория-проект. Путь (как есть или относительно базовой директории) — существующая директория, содержащая kumir.toml. Разрешается главный файл проекта (§ 3.5) и импортируется как модуль: его публичные алгоритмы и классы становятся доступными.
2 Файл .kum. Путь оканчивается на .kum, начинается с ./ или ../, либо содержит / или \. Импортируется как файловый модуль (§ 3.4).
3 Пользовательская библиотека. Путь — существующая директория либо содержит разделитель каталогов, но не подошёл под п. 1–2. Загружается как библиотека: директория с kumir.toml — как библиотека-проект, иначе как файл.
4 Встроенная библиотека. Простое имя, распознаваемое как известная библиотека по русскому или английскому имени либо алиасу. Загружается библиотека из реестра.
5 Иначе Ошибка: «Модуль или библиотека '<путь>' не найдены».

3.4. Разрешение пути файлового модуля

  • Относительный путь (./, ../) присоединяется к базовой директории;
  • абсолютный путь берётся как есть;
  • простое имя ищется по всем директориям поиска; дополнительно проверяется вариант «директория с файлом index.kum».

Расширение .kum подставляется автоматически, если его нет: сперва проверяется <путь>.kum, затем файл без расширения.

Базовой директорией запускаемого файла ДОЛЖЕН быть каталог этого файла: относительные импорты разрешаются относительно расположения импортирующего файла, а не текущего каталога процесса. Базовая директория всегда входит в список директорий поиска.

3.5. Главный файл проекта

  1. Если kumir.toml задаёт главный файл ([build] main либо [project]/[package] main) и этот файл существует — берётся он;
  2. иначе проверяются общепринятые расположения в порядке src/lib.kum → lib.kum → src/main.kum → main.kum;
  3. главным становится первый существующий файл.

3.6. Регистрация имён и пространства имён

После загрузки модуля его публичные имена регистрируются в среде исполнения. Пространство имён модуля — это префикс с точкой (Алиас.имя или ИмяМодуля.имя), а не отдельная область видимости.

Форма импортаРегистрация алгоритмов
С алиасом … как Алиас Только под именем Алиас.имя: пространство имён обязательно.
Без алиаса И под именем ИмяМодуля.имя, и под коротким имя: короткие имена вливаются в текущее пространство.
Выборочный : имя1, имя2 Каждое перечисленное имя регистрируется как Префикс.имя.

Имя модуля по умолчанию — имя файла без расширения; при наличии алиаса им становится алиас. Эталонное правило регистрации: Префикс.имя для алгоритмов, короткое имя для классов. Навешивание префикса на классы зависит от формы импорта, поэтому программа НЕ ДОЛЖНА обращаться к импортированному классу по полному имени. экспериментально

3.7. Доступ к членам модуля

Язык определяет два оператора доступа к члену. Обе формы разрешаются в одно и то же имя.

ФормаРазборРазрешениеСтабильность
Алиас.функция(…)
точка		 Точка становится частью имени: вызов алгоритма Алиас.функция. Ищется алгоритм с полным именем Алиас.функция, зарегистрированный при импорте. стабильно
Модуль::член
двойное двоеточие		 Доступ к члену модуля; вызов Модуль::функция(…) — вызов алгоритма модуля. Обе формы приводятся к точечному полному имени Модуль.член и разрешаются как точечная запись. стабильно 
подключить "./математика.kum" как мат

алг Тест
нач
    вывод мат.квадрат(5)   | вызов алгоритма "мат.квадрат"
    вывод мат::квадрат(5)  | то же имя "мат.квадрат"
кон

Записи Модуль.член и Модуль::член обращаются к одному и тому же члену. Порядок разрешения Модуль::член в позиции значения: вариант перечисления → переменная модуля под полным именем → алгоритм модуля (ошибка с указанием вызвать его) → ошибка «член не найден», называющая и модуль, и член. Для вызова Модуль::член(…): алгоритм → вариант перечисления с данными → функция загруженной библиотеки. Этой же формой записываются литералы вариантов перечисления Перечисление::Вариант (KITE 11).

Функции библиотек регистрируются под полным именем библиотека::функция и под короткими алиасами; правила вызова библиотечных функций нормированы в KITE 5.

3.8. Видимость и экспорт

Если файл не содержит инструкции экспорт, публичны все его алгоритмы и классы. Инструкция экспорт имя1, имя2, … в глобальной области файла ограничивает публичный набор перечисленными именами: экспортируется только то, что в списке. стабильно 

экспорт квадрат, куб      | только эти два алгоритма видны при импорте

алг цел квадрат(цел x) нач знач := x * x кон
алг цел куб(цел x)    нач знач := x * x * x кон
алг цел приватный(цел x) нач знач := x кон   | не экспортирован → не виден извне

Лексема экспорт имеет написания export и pub. В файловом модуле она задаёт список публичных имён; модификатором отдельного объявления (pub алг …) она не является — фильтрация выполняется по единому списку экспорт.

3.9. Именованные модули модуль … кон

модуль Гео
    алг вещ площадь(вещ a, вещ b) нач знач := a * b кон
кон

алг Главный
нач
    вывод Гео.площадь(3, 4)   | 12
кон

Каждый алгоритм именованного модуля регистрируется дважды: под полным именем Модуль.алг — для вызова снаружи, и под коротким именем алг — для вызова внутри модуля. Тело модуля (глобальные объявления) исполняется сразу. стабильно

Внутри модуль … кон все алгоритмы публичны: инструкция экспорт публичный набор именованного модуля не ограничивает. Сужение публичного набора именованного модуля — предложено.

3.10. Манифест проекта kumir.toml

Манифест kumir.toml описывает проект. Все ключи допускают двуязычные имена — английские и русские. Манифест ищется вверх по дереву каталогов от стартовой директории.

Секции [project], [package], [проект] — метаданные проекта; все три заголовка взаимозаменяемы.

Разрешение главного файла. Если main — абсолютный путь, он берётся как есть; иначе он присоединяется к корню проекта (каталогу манифеста). Этот путь использует резолвер импорта директории-проекта (§ 3.5).

Прочие секции. Манифест допускает [dependencies] / [зависимости] (версия, path, git, registry, features), [dev-dependencies], [build-dependencies], [workspace] / [рабочее_пространство], [registries], [env], а также lock-файл. Эти секции разбираются, но в резолюции импорта (§ 3.3) не участвуют: резолвер работает только с локальными путями и встроенными библиотеками. Разрешение зависимостей, реестры пакетов и workspaces — предложено; управление пакетами — предмет KITE 5 § 10. 

[project]
name = "моя_библиотека"
version = "1.0.0"
authors = ["Ученик"]

[build]
main = "src/lib.kum"

3.11. Кэш, циклы и инициализация

  • Кэш модулей. Загруженные файлы кэшируются по абсолютному пути. Повторный импорт того же файла даёт уже загруженный модуль: файл разбирается один раз. стабильно
  • Обнаружение циклов. Циклические зависимости между файловыми модулями запрещены: импорт файла, уже находящегося в цепочке импортов, ДОЛЖЕН давать ошибку «Циклический импорт: <путь>». стабильно
  • Инициализация модуля. При загрузке файлового модуля из него берутся только алгоритмы и классы. Глобальный код верхнего уровня файла при импорте не исполняется, поэтому глобальные переменные и побочные эффекты импортируемого файла импортирующему коду недоступны. Исполнение инициализации модуля — предложено.

Обнаружение циклов относится к файловым модулям; библиотеки загружаются реестром библиотек, и циклов между ними по построению нет (KITE 5).

3.12. Ограничения модульной системы

Язык сегодня не допускает следующего.

  • Из перегруженных реализаций алгоритма модуля импортируется только первая; прочие реализации импортирующему коду недоступны. экспериментально
  • Полное имя импортированного класса не гарантируется: класс доступен под своим коротким именем (§ 3.6).
  • Импорт без алиаса вливает короткие имена в текущее пространство. Поведение при совпадении коротких имён двух модулей язык не определяет; программа НЕ ДОЛЖНА на него полагаться и СЛЕДУЕТ импортировать такие модули с алиасом (§ 3.6). нестабильно
  • Инструкция экспорт не ограничивает публичный набор именованного модуля (§ 3.9).
  • Глобальные переменные импортируемого файла не инициализируются (§ 3.11).
  • Зависимости, реестры, workspaces и lock-файл в резолюции импорта не участвуют (§ 3.10).
  • Циклический импорт между файловыми модулями запрещён и диагностируется; частичное разрешение цикла язык не выполняет (§ 3.11).

5. Совместимость

КуМир 2 модульной системы не имеет: использовать, подключить, модуль и экспорт — расширения Kumir 3. В Kumir 3 эти слова являются ключевыми и именами переменных или алгоритмов быть НЕ МОГУТ. Программа без импортов сохраняет поведение КуМир 2; правила режима совместимости нормированы в KITE 6.

Возможность с меткой стабильно подчиняется гарантиям KITE 0 § 5.5. Для возможностей с прочими метками гарантии не действуют, и программа НЕ ДОЛЖНА на них полагаться.
