1. Философия типов

Kumir 3 использует градуальную типизацию: можно писать с авто и любой, а можно — со строгими типами и проверкой совместимости. В ядре статический дескриптор TypeKind зеркалит рантайм-значение Value, поэтому любое значение умеет сообщить свой тип. Рефлексия сегодня строковая: тип(x) возвращает имя типа; полноценных типов-значений первого класса пока нет (§10).

Движок реализован «Умный детектор» вместо большого match уже есть: расширяемый движок правил (shared/src/typesys) — совместимость, унификация, приведение, типизация операций. Подробности — в KITE 10. Этот документ описывает сами типы; движок описывает отношения между ними.

2. Числовые типы

На поверхности языка сегодня есть два числовых ключевых слова: цел (знаковое целое, 64 бита) и вещ (вещественное, 64 бита). Внутренний движок (Number/TypeKind) уже умеет ширины от 8 до 128 бит, но размерных имён типов в лексике и парсере пока нет: запись цел_8 x будет разобрана как пользовательский тип с именем цел_8, а не как 8-битное целое.

Честно о размерных типах Все строки 📋 выше — план, а не текущая возможность. Реализация свелась бы к добавлению лексем и ветвей разбора типов (движок чисел готов). Пока таких имён в программе писать нельзя.

Применение (после реализации): малые целые (цел_8/16) экономят память в таблицах; цел_128 и вещ_128 — для криптографии, точных вычислений и олимпиадных задач.

6. Владение и изменяемость

Каждое значение имеет состояние владения и признак изменяемости (ValueMeta).

ВладениеOwnedЗначение владеет ресурсом (по умолчанию). Существует только как метаданные ValueMeta; поведения, зависящего от владения, нет.🧪

Перемещениеперемещение · MovedПередача владения, источник инвалидируется. Выражение разбирается, но не вычисляется.📋
Изменяемостьизмен / констМожно ли менять значение. Константы защищены окружением (см. KITE 4 §5).✅
Копированиеклонировать / копироватьГлубокая копия / поверхностная для простых типов. Выражения разбираются, но не вычисляются.📋
Открытый вопрос: судьба «мёртвых» лексем перемещение, заимствовать, клонировать, копировать, &T присутствуют в лексике и AST, но никогда не исполнялись. Стандарт обязан выбрать: реализовать модель владения — либо перевести раздел в статус Withdrawn (см. KITE 0 §4). До принятия решения эти конструкции не следует использовать и рекламировать.

11. Правила совместимости

  • Тождество: одинаковые типы совместимы.
  • любой/авто: принимают любое значение.
  • пусто → T?: null допустим там, где ждут Option.
  • Числовое расширение: меньший числовой тип присваивается большему совместимой категории (напр. цел_16 → цел_64; целое → вещественное большего размера).
  • Общий тип: для бинарных операций выбирается тип большего размера/точности.
Это правила движка типов, а не текущего вычислителя Правила выше описывают движок типов (KITE 10); арифметика интерпретатора его пока не использует. Практические следствия: 7 / 2 всегда даёт вещественное 3.5 (целочисленное деление — это отдельный оператор див), а тип результата ** зависит от операндов. Нормативный источник по семантике операций и типу результата — KITE 13; при расхождении текстов прав KITE 13.
Без скрытых сужений Сужающие преобразования (например цел_64 → цел_8) не происходят автоматически — нужно явное приведение.
