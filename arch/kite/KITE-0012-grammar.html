1. Область применения

Документ определяет форму программ на Kumir 3: лексическую структуру (символы, лексемы, токены) и синтаксис (правила составления объявлений, инструкций и выражений из токенов). Текст, не порождаемый правилами настоящего документа, программой на Kumir 3 не является.

Документ не решает следующих вопросов:

  • смысл операций, порядок вычисления и тип результата — в KITE 13;
  • модель ошибок и поведение попытка/перехват/бросить — в KITE 14;
  • резолюция импортов и пространства имён — в KITE 15;
  • набор типов и их смысл — в KITE 2;
  • объектная модель — в KITE 11;
  • асинхронные конструкции — в KITE 3;
  • соглашения об оформлении программ — в KITE 8.

2. Термины и обозначения

Лексема — последовательность символов исходного текста. Токен — единица потока, порождаемая лексическими правилами и потребляемая синтаксическими. Продукция — правило грамматики. Разбор — построение дерева программы по продукциям настоящего документа.

Ключевые слова требований — ДОЛЖЕН, НЕ ДОЛЖЕН, СЛЕДУЕТ, МОЖЕТ — применяются в значении KITE 0 § 2.2. Метки стабильности — по KITE 0 § 5; в настоящем документе метка относится к форме (наличию продукции), а не к её исполнению. Метка стоит в строке таблицы или в заголовке пункта и в тексте не повторяется.

2.1. Нотация EBNF

Продукции записываются расширенной EBNF со следующими метасимволами:

rule = … ;Определение продукции; завершается ;.

2.2. Два уровня грамматики

Лексические правила (§ 3.1–§ 3.6) работают над потоком символов и порождают токены. Синтаксические правила (§ 3.7–§ 3.21) работают над потоком токенов. Терминалами синтаксиса служат имена классов токенов (INT, IDENT) либо канонические написания ключевых слов и операторов в кавычках ("алг", ":=").

3. Нормативные правила

3.1. Лексическая структура

Исходный текст ДОЛЖЕН быть закодирован в UTF-8. Лексический разбор идёт посимвольно; пробелы, кроме значимых переводов строк, токенов не порождают. На каждой позиции класс токена выбирается в фиксированном порядке: комментарий → перевод строки → строка/символ/raw/f-строка → число → идентификатор или ключевое слово → оператор → Rust-вставка. 

токен       = комментарий | NL | литерал | идентификатор
            | ключевое_слово | оператор | rust_вставка ;

пробел      = " " | "\t" | "\r" ;   (* не порождает токен *)

Символ \n порождает отдельный токен NL; переводы строк разделяют инструкции. Символ ; лексируется как отдельный оператор, но разделителем инструкций не является. Продолжения строки обратным слэшем язык не имеет.

3.2. Идентификаторы и ключевые слова

Идентификатор начинается с буквы (любой Unicode-буквы, включая кириллицу) или _ и продолжается буквами, цифрами, _ и комбинирующими диакритическими знаками. Нормализация NFC не применяется: сравнение идентификаторов побайтовое. 

идентификатор = ид_начало { ид_продолжение } ;

ид_начало     = ? Unicode-буква ? | "_" ;
ид_продолжение = ? Unicode-буква ? | ? Unicode-цифра ? | "_"
              | ? комбинирующий знак ? ;

Лексема, совпавшая с написанием ключевого слова, ДОЛЖНА давать токен этого ключевого слова; иначе она даёт обобщённый идентификатор. Язык определяет 103 ключевых слова; каждое имеет каноническое русское написание и МОЖЕТ иметь дополнительные написания — всего 295. Написания регистрозависимы (алг = alg = algorithm).

Категоризация идентификаторов Лексический уровень категоризацию идентификаторов по регистру или суффиксам не выполняет: не-ключевое слово всегда даёт обобщённый идентификатор, а роль имени (переменная, тип, функция) определяется контекстом при разборе. Правило «класс — с прописной буквы» — соглашение оформления (KITE 8), а не лексическое правило.

Отдельные слова дают операторные токены, а не самостоятельные ключевые слова:

3.3. Литералы

Числовые литералы допускают разделитель _ между цифрами во всех системах счисления; разделитель отбрасывается перед разбором значения. 

целое      = дес_целое | шестн | двоичн | восьмер ;

дес_целое  = цифра { [ "_" ] цифра } ;
шестн      = ( "0x" | "0X" ) hex_цифра { [ "_" ] hex_цифра } ;
двоичн     = ( "0b" | "0B" ) бит      { [ "_" ] бит } ;
восьмер    = ( "0o" | "0O" ) вось_цифра { [ "_" ] вось_цифра } ;

вещественное = дес_целое "." дробная [ экспонента ]
             | дес_целое экспонента ;
дробная    = цифра { [ "_" ] цифра } ;
экспонента = ( "e" | "E" ) [ "+" | "-" ] цифра { [ "_" ] цифра } ;

цифра      = "0"…"9" ;
hex_цифра  = "0"…"9" | "a"…"f" | "A"…"F" ;
вось_цифра = "0"…"7" ;
бит        = "0" | "1" ;

Целые литералы разбираются в i64, вещественные — в f64. Десятичная точка ДОЛЖНА иметь цифры с обеих сторон: 3.14 корректно, 3. — нет. Форма с экспонентой без точки (1e10) относится к вещественным литералам. Разделитель разрядов (1_000_000) допустим во всех системах счисления. стабильно

Логические и специальные литералы являются ключевыми словами:

лог_литерал   = "да" | "нет" ;                 (* true / false *)
пусто_литерал = "Пусто" | "пусто" | "ничего" | "null" | "nil" ;

3.4. Строки и интерполяция

Язык определяет пять форм строковых и символьных литералов.

строка        = '"' { символ_строки | экранир } '"' ;
многострочная = '"""' { ? любой символ, включая \n ? } '"""' ;
сим_литерал   = "'" ( символ | экранир ) "'" ;   (* ровно один символ *)

raw_строка    = "r" { "#" } '"' { ? любой символ ? } '"' { "#" } ;
              (* число закрывающих # равно числу открывающих; без экранирования *)

f_строка      = 'f"' { f_текст | "{{" | "}}" | "{" выражение "}" } '"' ;

экранир = "\n" | "\r" | "\t" | "\\" | "\"" | "\'" | "\0"
        | "\x" hex_цифра hex_цифра
        | "\u{" hex_цифра { hex_цифра } "}" ;   (* 1–6 цифр *)

3.5. Комментарии, пробелы, переводы строк

Язык определяет три вида строчных комментариев; блочных комментариев в языке нет.

комментарий      = pipe_комментарий | slash_комментарий | doc_комментарий ;

pipe_комментарий = "|" { ? любой символ до конца строки ? } ;  (* но не "|>" *)
slash_комментарий= "//" { ? …до конца строки ? } ;
doc_комментарий  = "///" { ? …до конца строки ? } ;

Одиночная | начинает комментарий классического КуМира, а последовательность |> — оператор конвейера, а не комментарий. Последовательность /// даёт doc-комментарий, // — обычный.

3.6. Операторы и разделители

Операторы лексируются жадно: сначала пробуется трёхсимвольное написание, затем двухсимвольное, затем односимвольное. Таблица операторов содержит 49 написаний; полный набор терминалов:

КатегорияТерминалы
Арифметика+ - * / % **, слова мод (%) и див (целочисленное деление)
Сравнение= == <> != < > <= >=
Присваивание:= += -= *= /= %=, а также <<= >>= (→ Assign)
Логика/словаи или не, символьные && ||
Диапазон.. ..= ...
Функц. / null|> (pipe), >> (compose), ?? (coalesce), ?. (safe), ? (propagate)
Стрелки / доступ-> => :: .
Сигилы@ & ^ ~
Скобки/разделители( ) [ ] { } , : ;

Разные написания МОГУТ давать один и тот же токен: <> и != дают NotEqual; = и == — Equal; ~ и ! — Not; %=, <<=, >>= — обобщённый Assign.

3.7. Структура программы

Программа — последовательность элементов верхнего уровня, разделённых переводами строк. Обязательного заголовка программы язык не требует. Если ни одного алг в исходном тексте нет, весь текст оборачивается в анонимный алгоритм (§ 5). 

программа   = { NL } { элемент_вп { NL } } ;

элемент_вп  = импорт
            | алгоритм
            | класс_декл
            | структура_декл
            | интерфейс_декл
            | трейт_декл
            | реализация_декл
            | модуль_декл
            | перечисление_декл
            | глоб_объявление        (* type name … на верхнем уровне *)
            ;

импорт      = ( "подключить" | "использовать" ) импорт_цель ;

Формы подключить и использовать (файл, каталог, библиотека, алиас) разбираются полностью; их резолюция нормирована в KITE 15 и KITE 5.

3.8. Алгоритмы и функции

Заголовок алгоритма МОЖЕТ указывать тип результата перед именем (классическая запись) или после списка параметров через : (современная запись). Секции дано и надо задают необязательные пред- и постусловия. 

алгоритм    = "алг" [ "асинх" ] [ тип ] имя [ "(" [ параметры ] ")" ] [ ":" тип ]
              { NL }
              [ "дано" выражение { NL } ]
              [ "надо" выражение { NL } ]
              "нач" { NL }
                блок
              "кон" ;

параметры   = параметр { "," параметр } ;

параметр    = режим тип имя [ "=" выражение ]        (* классически: арг цел x *)
            | имя ":" тип [ "=" выражение ] ;         (* современно: x: цел *)

режим       = [ "арг" | "рез" | "аргрез" ] ;

3.9. Объявления переменных и типов

объявление  = тип_объявление | авто_объявление | конст_объявление ;

тип_объявление  = тип имя { "," имя } [ ":=" выражение ] ;  (* init — только для одной переменной *)
авто_объявление = ( "авто" | "пусть" ) имя ":=" выражение ;
конст_объявление= "конст" тип имя ":=" выражение ;

Несколько имён МОГУТ перечисляться через запятую (цел a, b, c), но инициализатор := допустим только при одном имени. Слово пусть — дополнительное написание авто (вывод типа). Массивы объявляются таб-типом (§ 3.18); границы вида [1:10] разбираются в составе типа и индексации.

3.10. Инструкции

Тело алгоритма — последовательность инструкций, разделённых переводами строк.

блок        = { NL } { инструкция { NL } } ;

инструкция  = объявление
            | присваивание
            | вызов_инстр
            | если_инстр    | выбор_инстр   | совпадение_инстр
            | цикл_инстр
            | ввод_инстр     | вывод_инстр
            | вернуть_инстр  | знач_инстр
            | утв_инстр      | пауза_инстр   | выход_инстр
            | попытка_инстр  | бросить_инстр
            | прервать       | продолжить
            | экспорт_инстр
            | удалить_инстр   | ждать_инстр
            | rust_вставка ;

присваивание = цель_присв оп_присв выражение ;
оп_присв     = ":=" | "+=" | "-=" | "*=" | "/=" | "%=" ;
цель_присв   = выражение ;   (* переменная, индекс a[i], поле o.f *)

3.11. Условие и выбор

если_инстр = "если" выражение { NL } "то" { NL } блок
             [ "иначе" { NL } блок ] "все" ;

выбор_инстр = "выбор" { NL }
                { "при" выражение [ ":" ] { NL } блок }

3.16. Выражения

Выражения разбираются методом восходящих приоритетов: бинарный слой над унарным, унарный над постфиксным, постфиксный над первичным. 

выражение   = бинарное ;

бинарное    = унарное { бин_оп унарное } ;   (* с учётом приоритета и ассоциативности, § 3.17 *)

бин_оп      = "+" | "-" | "*" | "/" | "%" | "мод" | "**" | "див"
            | "=" | "==" | "<>" | "!=" | "<" | ">" | "<=" | ">="
            | "и" | "или"
            | ".." | "..=" | "|>" | ">>" | "??" ;

диапазон_шаг = бинарное [ "шаг" бинарное ] ;  (* a..b шаг c *)

унарное     = ( "-" | "не" | "&" | "&" "измен" | "^"
              | "новый" | "перемещение" | "клонировать" | "копировать"
              | "заимствовать" [ "измен" ] ) унарное
            | постфиксное ;

постфиксное = первичное { постфикс } ;

постфикс    = "(" [ аргументы ] ")"          (* вызов / вызов метода *)
            | "[" выражение { "," выражение } "]"  (* индексация *)
            | "." имя                          (* доступ к полю *)
            | "?." имя [ "(" [ аргументы ] ")" ]    (* безопасный доступ / вызов *)
            | "::" имя                          (* доступ к модулю/варианту *)
            | "как" тип                          (* приведение *)
            | "это" тип                          (* проверка типа: 5 это цел *)
            | "?" ;                              (* ранний возврат ошибки *)

аргументы   = выражение { "," выражение } ;

Формы Имя::член и Имя::член(…) разрешаются в то же полное имя, что и точечная запись Имя.член; правила разрешения нормированы в KITE 15. Этой же формой записываются литералы вариантов перечисления: Перечисление::Вариант и Перечисление::Вариант(x) (KITE 11).

Первичные выражения.

первичное = INT | FLOAT | STRING | RAW_STRING | CHAR | f_строка

Двойная роль это. Лексема это в первичной позиции — ссылка на текущий объект; в постфиксной позиции после операнда — проверка типа (5 это цел). Дизамбигуация выполняется по позиции: постфиксная позиция означает проверку типа, первичная — ссылку на объект.

3.17. Приоритет и ассоциативность

Больший уровень связывает сильнее. Правоассоциативны только ** и ??. Унарные операторы связывают сильнее любого бинарного; постфиксы ((), [], ., ::) — сильнее унарных. Приведённая таблица — единственная нормативная таблица приоритетов языка.

3.20. Паттерны

Паттерны применяются в инструкции и выражении совпадение. Верхний уровень паттерна допускает or-паттерны, типовую аннотацию и охрану. 

паттерн       = or_паттерн [ ":" тип ] [ "если" выражение ] ;
or_паттерн    = атом_паттерн { "|" атом_паттерн } ;

атом_паттерн  = "_"                                   (* wildcard *)
              | ".."                                  (* rest *)
              | [ "-" ] INT | FLOAT | STRING | CHAR   (* литерал, вкл. отрицательный *)
              | "да" | "нет"
              | пусто_литерал
              | "Some" "(" паттерн ")"
              | "Ok" "(" паттерн ")" | "Err" "(" паттерн ")"
              | "(" [ паттерн { "," паттерн } ] ")"   (* пара/тройка/кортеж *)
              | "[" [ паттерн { "," паттерн } [ "," ".." [ имя ] ] ] "]"  (* массив с rest *)
              | "&" [ "измен" ] паттерн            (* ссылка *)
              | "^" паттерн                            (* разыменование *)
              | "измен" имя                            (* изменяемая привязка *)
              | имя "@" паттерн                        (* привязка @ *)
              | INT ( ".." | "..=" ) INT               (* диапазон *)
              | имя "{" поле_паттерн { "," поле_паттерн } [ "," ".." ] "}"  (* структурный *)
              | имя "::" имя [ "(" паттерн { "," паттерн } ")" ]            (* вариант перечисления *)
              | имя ;                                  (* привязка переменной *)

поле_паттерн  = имя [ ":" паттерн ] ;

Продукции выше задают около двадцати трёх разновидностей паттернов: wildcard, rest, литералы (в том числе отрицательные), Some/Ok/Err, кортежные, массивные с хвостом ..имя, ссылочные, разыменование, изменяемые привязки, @-привязки, типизированные, диапазонные, структурные, варианты перечислений, or-паттерны и охраны если. Сопоставление значений с паттернами нормировано в KITE 13. стабильно

5. Совместимость

Форма записи КуМир 2 сохранена: классический заголовок алгоритма с типом результата перед именем и режимами арг/рез/аргрез (§ 3.8), инструкции если … то … все, выбор … при … все, нц … кц (§ 3.11, § 3.12), комментарий, начинающийся с | (§ 3.5), и имена примитивных типов (§ 3.18).

Исходный текст, не содержащий ни одного алг, оборачивается в анонимный алгоритм (§ 3.7): простая программа КуМир 2 из одних инструкций остаётся корректной. Правила режима совместимости с КуМир 2 нормированы в KITE 6.

Последовательность |> в Kumir 3 — оператор конвейера, а не начало комментария (§ 3.5): текст КуМир 2, в котором за | сразу следует >, меняет смысл. Слово див — оператор (§ 3.2) и именем переменной или алгоритма быть НЕ МОЖЕТ.

Возможность с меткой стабильно подчиняется гарантиям KITE 0 § 5.5. Для возможностей с прочими метками гарантии не действуют, и программа НЕ ДОЛЖНА на них полагаться.
