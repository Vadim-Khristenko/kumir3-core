1. Введение и статус

Этот документ нормативно фиксирует фактическую грамматику языка Kumir 3 — такую, какую разбирают лексер (shared/src/lexer/) и парсер (shared/src/parser/) ядра. Грамматика извлечена из кода, а не придумана: если продукция ниже расходится с поведением разборщика — это баг (грамматики или кода), а не свобода трактовки.

Грамматика — основа для второго фронтенда (LSP, форматтер, линтер), conformance-тестов и режима совместимости. Данный документ описывает синтаксис; семантику операций описывает KITE 13, ошибки — KITE 14, модули — KITE 15, типы — KITE 2.

Статус — Draft Грамматика извлечена из парсера (~6.3k строк) и лексера (~2.4k строк) и станет Active после покрытия conformance-тестами. До тех пор возможны неполноты в редко используемых ветках (например, точная форма generic-ограничений где).

2. Нотация EBNF

Используется единая, слегка расширенная EBNF. Ниже — значения метасимволов:

ЗаписьСмысл
rule = … ;Определение продукции; завершается ;.
"текст"Терминал — точная последовательность символов (лексема/оператор).
ИМЯ (прописными)Терминальный класс токена лексера (например INT, IDENT).
a bКонкатенация: a, затем b.
a | bАльтернатива: a или b.
[ a ]Необязательно (0 или 1).
{ a }Повторение (0 или более).
( a )Группировка.
a - bРазность: a, но не b (в лексических правилах).
? описание ?Внеконтекстное условие словами (например класс Unicode).
NLТерминал «значимый перевод строки» (Token::Newline).
Два уровня Лексические правила (разделы 3–8) работают над потоком символов и порождают токены. Синтаксические правила (разделы 9–17) работают над потоком токенов. Терминалы синтаксиса — это либо имена классов токенов (INT, IDENT), либо канонические написания ключевых слов и операторов в кавычках ("алг", ":=").

3. Лексическая грамматика

Лексер сканирует UTF-8 посимвольно (lexer/scanner.rs), пропускает пробелы (кроме значимых переводов строк), затем на каждой позиции выбирает один из классов токенов. Порядок попыток фиксирован: комментарий → перевод строки → строка/сим/raw/f-строка → число → идентификатор или ключевое слово → оператор → Rust-вставка. 

токен       = комментарий | NL | литерал | идентификатор
            | ключевое_слово | оператор | rust_вставка ;

пробел      = " " | "\t" | "\r" ;   (* не порождает токен *)
Значимые переводы строк Символ \n порождает отдельный токен NL (lexer/mod.rs): переводы строк разделяют инструкции. ; лексируется как отдельный оператор Token::SemiColon, но парсером как разделитель инструкций не используется. Продолжения строки обратным слэшем нет.

4. Идентификаторы и ключевые слова

Идентификатор начинается с буквы (любой Unicode-буквы, включая кириллицу) или _, продолжается буквами, цифрами, _ и комбинирующими диакритическими знаками (lexer/identifiers.rs). Нормализация NFC не применяется — сравнение побайтовое. 

идентификатор = ид_начало { ид_продолжение } ;

ид_начало     = ? Unicode-буква ? | "_" ;
ид_продолжение = ? Unicode-буква ? | ? Unicode-цифра ? | "_"
              | ? комбинирующий знак ? ;

После сканирования лексема сверяется с phf-таблицей ключевых слов (KEYWORD_INDEX, сгенерирована из build.rs::KEYWORDS — 193 написания). Совпадение даёт конкретный токен ключевого слова; иначе — Token::Ident. Ключевые слова регистрозависимы, но у многих есть и русское каноническое, и латинские алиасы (алг = alg = algorithm).

Категоризация идентификаторов Тип токена token.rs различает NamespaceIdent/ClassIdent/FuncIdent/TypeIdent/VarIdent/Ident, но лексер категоризацию по регистру/суффиксам не выполняет: не-ключевое слово всегда становится обобщённым Ident; роль (переменная, тип, функция) определяет парсер и рантайм по контексту. Правило «класс с прописной буквы» — соглашение стиля (KITE-8), не лексическое правило.

Некоторые слова-операторы лексируются в операторные токены, а не в отдельные ключевые слова:

СловоТокенСмыслРазбор
и / или / неAnd/Or/NotЛогические операторы.✅
модPercentОстаток от деления (как %).✅
дивIntDivЦелочисленное деление (только русское див; латинское div — имя встроенной функции).✅

5. Литералы

Числовые литералы допускают разделитель _ между цифрами во всех системах счисления (lexer/numbers.rs). Разделитель вырезается перед разбором значения.

целое      = дес_целое | шестн | двоичн | восьмер ;

дес_целое  = цифра { [ "_" ] цифра } ;
шестн      = ( "0x" | "0X" ) hex_цифра { [ "_" ] hex_цифра } ;
двоичн     = ( "0b" | "0B" ) бит      { [ "_" ] бит } ;
восьмер    = ( "0o" | "0O" ) вось_цифра { [ "_" ] вось_цифра } ;

вещественное = дес_целое "." дробная [ экспонента ]
             | дес_целое экспонента ;
дробная    = цифра { [ "_" ] цифра } ;
экспонента = ( "e" | "E" ) [ "+" | "-" ] цифра { [ "_" ] цифра } ;

цифра      = "0"…"9" ;
hex_цифра  = "0"…"9" | "a"…"f" | "A"…"F" ;
вось_цифра = "0"…"7" ;
бит        = "0" | "1" ;
Факты реализации Целые разбираются в i64, вещественные — в f64. Десятичная точка требует цифр с обеих сторон (3.14, не 3.). Форма с экспонентой без точки (1e10) классифицируется как вещественное. Разделитель 1_000_000 — ✅ во всех системах счисления.

Логические и специальные литералы — это ключевые слова:

лог_литерал   = "да" | "нет" ;                 (* true / false *)
пусто_литерал = "Пусто" | "пусто" | "ничего" | "null" | "nil" ; (* Token::None *)

6. Строки и интерполяция

Поддерживаются пять форм строковых/символьных литералов (lexer/strings.rs).

строка        = '"' { символ_строки | экранир } '"' ;
многострочная = '"""' { ? любой символ, включая \n ? } '"""' ;
сим_литерал   = "'" ( символ | экранир ) "'" ;   (* ровно один символ *)

raw_строка    = "r" { "#" } '"' { ? любой символ ? } '"' { "#" } ;
              (* число закрывающих # равно числу открывающих; без экранирования *)

f_строка      = 'f"' { f_текст | "{{" | "}}" | "{" выражение "}" } '"' ;

экранир = "\n" | "\r" | "\t" | "\\" | "\"" | "\'" | "\0"
        | "\x" hex_цифра hex_цифра
        | "\u{" hex_цифра { hex_цифра } "}" ;   (* 1–6 цифр *)
ФормаПримерОсобенностиРазбор
Строка"привет\n"Двойные кавычки; экранирование по таблице выше.✅
Многострочная"""…"""Тройные кавычки; переводы строк внутри разрешены.✅
Символ'а'Одинарные кавычки; ровно один символ, иначе ошибка.✅
Rawr#"C:\путь"#Префикс r + N решёток; без экранирования.✅
Интерполяцияf"x = {x+1}"Префикс f; {{/}} — литеральные скобки; вложенные выражения.✅
Префикс f обязателен Обычные строки не интерполируются: "привет, {имя}" — литеральный текст. Интерполяция включается только префиксом: f"привет, {имя}". F-строка лексируется в последовательность InterpolatedStringStart / …Part / вложенные токены выражения / …End и разбирается парсером в цепочку конкатенаций.

7. Комментарии, пробелы, переводы строк

Есть два вида строчных комментариев (lexer/comments.rs); блочных комментариев нет.

комментарий      = pipe_комментарий | slash_комментарий | doc_комментарий ;

pipe_комментарий = "|" { ? любой символ до конца строки ? } ;  (* но не "|>" *)
slash_комментарий= "//" { ? …до конца строки ? } ;
doc_комментарий  = "///" { ? …до конца строки ? } ;
Тонкость | Одиночная | начинает комментарий классического КуМира, но последовательность |> — это оператор конвейера (pipe), а не комментарий (lexer/mod.rs). /// даёт doc-комментарий (Token::DocComment), // — обычный.

8. Операторы и разделители

Операторы лексируются жадно (3 символа → 2 → 1) по phf-таблице build.rs::OPERATORS (39 записей). Полный набор терминалов:

КатегорияТерминалы
Арифметика+ - * / % **, слова мод (%) и див (целочисленное деление)
Сравнение= == <> != < > <= >=
Присваивание:= += -= *= /= %=, а также <<= >>= (→ Assign)
Логика/словаи или не, символьные && ||
Диапазон.. ..= ...
Функц. / null|> (pipe), >> (compose), ?? (coalesce), ?. (safe), ? (propagate)
Стрелки / доступ-> => :: .
Сигилы@ & ^ ~
Скобки/разделители( ) [ ] { } , : ;
Синонимы на уровне лексики Несколько символов могут давать один токен: <> и != → NotEqual; = и == → Equal; ~ и ! → Not; %=, <<=, >>= → обобщённый Assign.

9. Структура программы

Программа (parser/decl.rs) — это последовательность элементов верхнего уровня. Если ни одного алг нет, весь исходник оборачивается в анонимный алгоритм (совместимость с простыми КуМир-2 программами). Обязательного заголовка программы нет; переводы строк разделяют элементы. 

программа   = { NL } { элемент_вп { NL } } ;

элемент_вп  = импорт
            | алгоритм
            | класс_декл
            | структура_декл
            | интерфейс_декл
            | трейт_декл
            | реализация_декл
            | модуль_декл
            | перечисление_декл
            | глоб_объявление        (* type name … на верхнем уровне *)
            ;

импорт      = ( "подключить" | "использовать" ) импорт_цель ;
Импорты Формы подключить/использовать (файл, каталог, библиотека, алиас) полностью разбираются; их нормативная семантика и правила резолюции описываются отдельно в KITE 15 и KITE 5.

10. Алгоритмы и функции

Заголовок алгоритма допускает тип результата перед именем (классически) или после параметров через : (современно). Секции дано/надо — необязательные пред/постусловия.

алгоритм    = "алг" [ "асинх" ] [ тип ] имя [ "(" [ параметры ] ")" ] [ ":" тип ]
              { NL }
              [ "дано" выражение { NL } ]
              [ "надо" выражение { NL } ]
              "нач" { NL }
                блок
              "кон" ;

параметры   = параметр { "," параметр } ;

параметр    = режим тип имя [ "=" выражение ]        (* классически: арг цел x *)
            | имя ":" тип [ "=" выражение ] ;         (* современно: x: цел *)

режим       = [ "арг" | "рез" | "аргрез" ] ;

Современные параметрыалг f(x: цел, y: вещ): лог✅

11. Объявления переменных и типов

объявление  = тип_объявление | авто_объявление | конст_объявление ;

тип_объявление  = тип имя { "," имя } [ ":=" выражение ] ;  (* init — только для одной переменной *)
авто_объявление = ( "авто" | "пусть" ) имя ":=" выражение ;
конст_объявление= "конст" тип имя ":=" выражение ;
Списки и инициализация Несколько имён перечисляются через запятую (цел a, b, c), но инициализатор := допускается только при одной переменной. пусть — алиас авто (вывод типа). Массивы объявляются как таб-тип (раздел 15); синтаксис границ [1:10] разбирается в рамках типа/индексации.

12. Инструкции

Тело (parser/stmt.rs) — последовательность инструкций, разделённых переводами строк.

блок        = { NL } { инструкция { NL } } ;

инструкция  = объявление
            | присваивание
            | вызов_инстр
            | если_инстр    | выбор_инстр   | совпадение_инстр
            | цикл_инстр
            | ввод_инстр     | вывод_инстр
            | вернуть_инстр  | знач_инстр
            | утв_инстр      | пауза_инстр   | выход_инстр
            | попытка_инстр  | бросить_инстр
            | прервать       | продолжить
            | экспорт_инстр
            | удалить_инстр   | ждать_инстр
            | rust_вставка ;

присваивание = цель_присв оп_присв выражение ;
оп_присв     = ":=" | "+=" | "-=" | "*=" | "/=" | "%=" ;

13. Выражения

Выражения разбираются восходящим методом приоритетов (Pratt / precedence-climbing, parser/expr.rs): бинарный слой над унарным, унарный над постфиксным, постфиксный над первичным. 

выражение   = бинарное ;

бинарное    = унарное { бин_оп унарное } ;   (* с учётом приоритета/ассоциативности, разд. 14 *)

бин_оп      = "+" | "-" | "*" | "/" | "%" | "мод" | "**" | "див"
            | "=" | "==" | "<>" | "!=" | "<" | ">" | "<=" | ">="
            | "и" | "или"
            | ".." | "..=" | "|>" | ">>" | "??" ;

диапазон_шаг = бинарное [ "шаг" бинарное ] ;  (* a..b шаг c *)

унарное     = ( "-" | "не" | "&" | "&" "измен" | "^"
              | "новый" | "перемещение" | "клонировать" | "копировать"
              | "заимствовать" [ "измен" ] ) унарное
            | постфиксное ;

постфиксное = первичное { постфикс } ;

постфикс    = "(" [ аргументы ] ")"          (* вызов / вызов метода *)
            | "[" выражение { "," выражение } "]"  (* индексация *)
            | "." имя                          (* доступ к полю *)
            | "?." имя [ "(" [ аргументы ] ")" ]    (* безопасный доступ / вызов *)
            | "::" имя                          (* доступ к модулю/варианту *)
            | "как" тип                          (* приведение *)
            | "это" тип                          (* проверка типа: 5 это цел *)
            | "?" ;                              (* ранний возврат ошибки *)

аргументы   = выражение { "," выражение } ;

13.1 Первичные выражения

первичное = INT | FLOAT | STRING | RAW_STRING | CHAR | f_строка
          | "да" | "нет" | пусто_литерал
          | "НеРеализовано" [ "(" STRING ")" ]
          | "НеДоступно"   [ "(" STRING ")" ]
          | "Устарело"     [ "(" STRING ")" ]
          | "я" | "это" | "предок"
          | идентификатор
          | "(" [ выражение { "," выражение } ] ")"   (* группа () или кортеж (a,b) *)
          | "[" [ выражение { "," выражение } ] "]"    (* литерал массива *)
          | лямбда
          | короткая_лямбда
          | если_выражение
          | совпадение_выражение
          | "новый" ( имя_класса "(" [ аргументы ] ")" | выражение )
          | "ждать" выражение
          ;

короткая_лямбда  = имя "=>" выражение
                 | "(" [ имя { "," имя } ] ")" "=>" выражение ;

совпадение_выражение = "совпадение" выражение { "при" паттерн "=>" выражение } "все" ;

13.2 Двойная роль это

Лексема это (Token::This) в первичной позиции — ссылка на себя (self); в постфиксной позиции после выражения — проверка типа: 5 это цел. Правило дизамбигуации: постфиксная позиция (после операнда) означает тип-чек, первичная — self.

14. Приоритет и ассоциативность

Приоритеты бинарных операторов заданы в parser/precedence.rs (binary_precedence): больший уровень связывает сильнее. Правоассоциативны только ** и ?? (is_right_associative). Унарные операторы связывают сильнее любого бинарного; постфиксы ((), [], ., ::) — сильнее унарных.

17. Паттерны (сопоставление)

Паттерны (parser/pattern.rs) используются в совпадение/при. Верхний уровень допускает or-паттерны, типовую аннотацию и охрану.

паттерн       = or_паттерн [ ":" тип ] [ "если" выражение ] ;
or_паттерн    = атом_паттерн { "|" атом_паттерн } ;

атом_паттерн  = "_"                                   (* wildcard *)
              | ".."                                  (* rest *)
              | [ "-" ] INT | FLOAT | STRING | CHAR   (* литерал, вкл. отрицательный *)
              | "да" | "нет"
              | пусто_литерал
              | "Some" "(" паттерн ")"
              | "Ok" "(" паттерн ")" | "Err" "(" паттерн ")"
              | "(" [ паттерн { "," паттерн } ] ")"   (* пара/тройка/кортеж *)
              | "[" [ паттерн { "," паттерн } [ "," ".." [ имя ] ] ] "]"  (* массив с rest *)
              | "&" [ "измен" ] паттерн            (* ссылка *)
              | "^" паттерн                            (* разыменование *)
              | "измен" имя                            (* изменяемая привязка *)
              | имя "@" паттерн                        (* привязка @ *)
              | INT ( ".." | "..=" ) INT               (* диапазон *)
              | имя "{" поле_паттерн { "," поле_паттерн } [ "," ".." ] "}"  (* структурный *)
              | имя "::" имя [ "(" паттерн { "," паттерн } ")" ]            (* вариант перечисления *)
              | имя ;                                  (* привязка переменной *)

поле_паттерн  = имя [ ":" паттерн ] ;
Разнообразие паттернов Парсер производит ~23 разновидности паттернов: wildcard, rest, литералы (в т.ч. отрицательные), Some/Ok/Err, кортежные (пара/тройка), массивные с хвостом ..имя, ссылочные, разыменование, изменяемые привязки, @-привязки, типизированные, диапазонные, структурные, варианты перечислений, or-паттерны и охраны если. Исполняется пока преимущественно enum-часть; полнота — предмет отдельной работы (аудит W0).

18. Rust-вставки

Kumir 3 умеет встраивать Rust-код двумя способами (lexer/rust_blocks.rs).

rust_вставка = "РастВставкаНЦ" ? код Rust ? "РастВставкаКЦ"
             | ( "ржавчина" | "Ржавчина" | "rust" ) "нач" ? код Rust ? "кон" ;
Границы слов Во второй форме нач и завершающий кон распознаются как отдельные слова (следующий символ не должен быть частью идентификатора). Незакрытая вставка — ошибка UnterminatedRustBlock. Разбор содержимого Rust не входит в эту грамматику.
