1. Мотивация

1.1. Какая задача не решается существующим языком

Kumir 3 отличается от КуМир 2 в местах, наблюдаемых программой: правила области видимости лексические (KITE 4), кодировка исходного текста и строк — UTF-8, система типов расширена (KITE 2), классические исполнители в окружении отсутствуют. Программа, написанная для КуМир 2, поэтому либо не исполняется, либо исполняется иначе.

Накопленный школьный материал — задачники, разборы, готовые решения — записан на КуМир 2. Язык, не исполняющий этот материал, вынуждает переписывать его целиком прежде, чем им можно пользоваться.

1.2. Что предлагается получить

  • Исполнение программ КуМир 2 без изменения их текста — совместимость по наблюдаемому поведению.
  • Переключение спорных решений — область видимости, кодировка, объявление переменных ведут себя так, как в КуМир 2.
  • Доступность классических исполнителей — Робот, Чертёжник и остальные доступны без явного подключения (KITE 17).
Режим не сокращает язык Режим совместимости не скрывает возможности Kumir 3: он изменяет поведение в перечисленных местах и подключает исполнителей. Возможности Kumir 3, не конфликтующие с семантикой КуМир 2, остаются доступны (§ 5).

2. Рассмотренные альтернативы

2.1. Отдельная реализация КуМир 2

Рассмотрен вариант, при котором старые программы исполняет отдельная программа-интерпретатор, а Kumir 3 совместимости не имеет. Вариант отклонён: два независимых языка расходятся, смешанный проект становится невозможным, а постепенный перевод учебного материала — тоже.

2.2. Совместимость по умолчанию

Рассмотрен вариант, при котором поведение КуМир 2 действует по умолчанию, а Kumir 3 включается явно. Вариант отклонён: он закрепляет за новыми программами старую семантику видимости и делает лексическую область видимости (KITE 4) исключением, а не правилом.

2.3. Автоматическое определение диалекта по тексту программы

Рассмотрен вариант, при котором режим выводится из содержимого файла — по употреблённым конструкциям или по кодировке. Вариант отклонён: вывод неоднозначен для программ, лежащих в пересечении диалектов, а изменение текста программы способно молча изменить её семантику. Принятый вариант — явное объявление режима (§ 3.1).

2.4. Режим на уровне проекта

Рассмотрен вариант, при котором режим задаётся только для проекта целиком. Вариант отклонён: он исключает постепенный перевод материала, при котором старые и новые файлы сосуществуют. Принятый вариант — режим на уровне файла (§ 3.4).

2.5. Директива в виде новой синтаксической конструкции

Рассмотрен вариант с отдельной конструкцией объявления режима. Вариант отклонён: файл с такой конструкцией перестаёт быть программой КуМир 2 и не исполняется в классической среде. Принятый вариант — директива в форме комментария (§ 3.2).

3. Предлагаемое решение предложено

Раздел описывает предлагаемое изменение целиком. Метка стабильности относится ко всему разделу и внутри него не повторяется. Поведение Kumir 3 без объявленного режима — это поведение языка по умолчанию, настоящим предложением не изменяемое.

3.1. Способы объявления режима и их приоритет

Режим объявляется тремя способами. Способ с меньшим номером имеет больший приоритет: объявление в файле перекрывает объявление запуска, объявление запуска перекрывает объявление проекта.

ПриоритетСпособОбласть действия
1 (наибольший)Директива-комментарий в начале файла (§ 3.2)Только этот файл
2Параметр запуска --режим кум2Весь запуск
3Поля edition и kumir_version в kumir.toml (§ 3.3)Весь проект
4 (по умолчанию)Режим не объявленKumir 3

3.2. Директива файла

Директива записывается как обычный комментарий Кумира (|), поэтому классическая среда КуМир 2 её пропускает и файл остаётся исполнимым без изменений. Директива ДОЛЖНА располагаться до первой непустой строки кода. 

| MODE: KUM2          | запись по-английски
| РЕЖИМ: КУМ2         | равнозначная запись по-русски

алг Главный
нач
  | код КуМир 2
кон

3.3. Объявление в kumir.toml

Поле edition принимает целое число: 2 — КуМир 2, 3 — Kumir 3. Поле kumir_version закрепляет точную версию семантики диалекта и записывается семантической версией. 

[package]
edition = 2                 # 2 — КуМир 2, 3 — Kumir 3
kumir_version = "2.1.0"     # точная версия семантики диалекта

3.4. Гранулярность и смешивание

Режим действует на уровне файла. Это допускает следующие сочетания:

  • Проект на Kumir 3 (по умолчанию либо через kumir.toml), отдельные файлы — в режиме совместимости через директиву.
  • Проект с edition = 2, отдельный новый файл — на Kumir 3 через директиву.
Границей режима служит модуль Режим определяется при загрузке файла и НЕ ДОЛЖЕН распространяться на импортируемые модули: каждый модуль объявляет свой режим самостоятельно.

3.5. Переключаемые различия поведения

АспектРежим совместимостиKumir 3 (по умолчанию)
Область видимости Стековая (динамическая) Лексическая (KITE 4)
Кодировка строк CP-1251 UTF-8
Объявление переменных Неявное создание при присваивании, без диагностики Неявное создание с предупреждением; строгий режим делает его ошибкой (KITE 4)
Набор типов цел, вещ, лог, сим, лит, таб Полная система типов (KITE 2)

Полнота перечня — открытый вопрос (§ 5). Семантика операторов Kumir 3, включая деление и округление, задана в KITE 13.

3.6. Исполнители в режиме совместимости

Классические исполнители — учебные миры с состоянием и набором команд. В режиме совместимости они входят в окружение файла без записи использовать; в Kumir 3 они подключаются явно.

ЧертёжникКоординатная плоскостьопустить перо, поднять перо, сместиться в точку

Модель исполнителя описана отдельно Обстановка, набор команд и запросов, условия отказа и формат файла обстановки задаются в KITE 17. Настоящий документ определяет только способ, которым исполнитель попадает в окружение.

3.7. Порядок определения режима при загрузке

Режим определяется один раз для файла и далее применяется на всех этапах его обработки:

  1. Режим файла устанавливается по правилам приоритета § 3.1.
  2. Разбор исходного текста выполняется в кодировке, соответствующей режиму (§ 3.5).
  3. Правила области видимости и объявления переменных применяются согласно режиму.
  4. Окружение исполнения пополняется исполнителями и совместимым набором встроенных имён (§ 3.6).
Зависимость от модели окружений Переключение области видимости опирается на модель окружений (KITE 4): режим совместимости восстанавливает стековое разрешение имён поверх лексического.

4. Влияние на совместимость

  • Программы Kumir 3 не затрагиваются. Файл, не объявивший режим, сохраняет поведение по умолчанию: предложение вводит новое поведение только для файлов, объявивших режим совместимости.
  • Программы КуМир 2 становятся исполнимыми. Текст программы не изменяется; директива § 3.2 остаётся комментарием и в классической среде.
  • Смешанный проект. Поскольку границей режима служит модуль (§ 3.4), файлы двух диалектов сосуществуют в одном проекте, и перевод материала выполняется по одному файлу за раз.
  • Проект без kumir.toml. Отсутствие файла проекта равносильно edition = 3; ранее собиравшиеся проекты собираются без изменений.
  • Диагностика перехода. Места программы, поведение которых различается между режимами, перечислены в § 3.5; переход файла на Kumir 3 требует проверки именно этих мест.

5. Открытые вопросы

  1. Полнота перечня различий. Какие ещё места поведения различаются между диалектами — округление, целочисленное деление, имена и значения встроенных величин? Перечень § 3.5 закрывается до принятия предложения.
  2. Возможности Kumir 3 внутри режима совместимости. Какие конструкции Kumir 3 допустимы в файле, объявившем режим КуМир 2, и какие запрещены как конфликтующие с семантикой диалекта?
  3. Значение kumir_version. Какие версии семантики КуМир 2 различимы и что происходит при указании неизвестной версии?
  4. Кодировка исходного текста. Определяется ли кодировка файла режимом целиком либо допускается файл КуМир 2 в UTF-8?

6. Статус

Предложение имеет статус Draft. Описанные возможности несут метку предложено: программа, полагающаяся на режим совместимости, корректной программой Kumir 3 не является.

Приняты решения: директива режима в форме комментария | MODE: KUM2 и | РЕЖИМ: КУМ2 (§ 3.2); числовое значение поля edition и отдельное поле kumir_version (§ 3.3); режим на уровне файла с границей по модулю (§ 3.4).

При принятии предложения нормативная часть § 3 переносится в Спецификацию режима совместимости, после чего настоящий документ нормы не задаёт. Вопросы § 5 разрешаются до переноса.
