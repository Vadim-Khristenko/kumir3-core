1. Легенда и источники истины

Легенда доступности ✅ Доступно — реализовано в движке и проверено тестами. 🧪 Экспериментально — реализовано, но с ограничениями/швами. 📋 Предложено — описано, но ещё не исполняется.

Этот документ фиксирует наблюдаемое поведение вычислителя выражений Kumir 3 — то, что сегодня живёт только в характеризационных тестах. Нормативным источником поведения служит файл interpreter/src/interpreter/typeops_characterization.rs (≈ 117 проверок, «каждое ожидаемое значение наблюдалось, а не угадано»). Реализация операций — shared/src/math/mod.rs (MathOperators) и слой interpreter/src/interpreter/ops/; порядок и спецформы — evaluator/.

Движок типов vs. рантайм В ядре есть статический движок типов (shared/src/typesys, см. KITE 10) с решётками расширения и result_of_binop/common_type. Однако рантайм-операции пока не проходят через него: в коде расставлены «швы» [typesys-seam] (ops/binary.rs, ops/cast.rs, ops/predicates.rs). Поэтому этот документ описывает фактическое поведение MathOperators, а не то, что предсказывает движок типов. Сведение обоих — предмет будущей адопции typesys.

2. Модель вычисления и порядок

Выражение — это дерево (Expr), вычисляемое рекурсивно функцией ExprEvaluator::evaluate в текущем окружении. Вычисление энергичное (eager): к моменту применения оператора его операнды уже вычислены в значения (Value). Исключения из энергичности — «ленивые» операторы и/или и обёрточные операторы ??, ?. (см. §3, §7).

2.1. Порядок вычисления операндов

  • Бинарные операции: сначала вычисляется левый операнд, затем правый, затем применяется оператор (evaluator/binary.rs: left_val до right_val). Порядок детерминирован: слева направо.
  • Аргументы вызовов, элементы литералов массива/кортежа: вычисляются по порядку следования, слева направо; первая же ошибка прекращает вычисление всего выражения (характеризация: элементы массива/кортежа вычисляются, не отбрасываются).
  • Побочные эффекты (ввод/вывод, изменение переменных внутри вызовов) наблюдаются в этом же порядке.
Нормативно Слева-направо и «первая ошибка останавливает вычисление» — гарантия языка, а не деталь реализации. Программы вправе на неё полагаться.

3. Короткое замыкание и / или

Логические и (AND) и или (OR) вычисляются лениво (evaluator/binary.rs):

  • a и b: вычисляется a; если a ложно — результат нет, а b не вычисляется. Иначе результат — истинность b.
  • a или b: вычисляется a; если a истинно — результат да, а b не вычисляется. Иначе результат — истинность b.
Результат всегда лог Оба оператора возвращают Boolean — истинность операнда, а не сам операнд. То есть x или y — это не «первое истинное значение», а именно да/нет. Операнды приводятся к истинности по правилам §12. ✅

4. Арифметика

Арифметические операторы делегируют в MathOperators (shared/src/math/mod.rs) через ops/binary.rs. Числовая часть унифицируется: для двух целых применяется целочисленная операция в общем типе, для смешанных/вещественных — вычисление в F128 (см. §11).

4.1. Сложение, вычитание, умножение

ОператорОперандыРезультатДост.
+число + числоЧисло в общем типе (см. §11). 2+3 → 5.✅
+строка + строкаКонкатенация. "ab"+"cd" → "abcd".✅
+массив + массивКонкатенация массивов.✅
−число − числоЧисло в общем типе. 10−4 → 6.✅
−строка − строкаУдаление всех вхождений подстроки (алгоритм KMP).🧪
−массив − массивУдаление элементов правого из левого (мультимножественно).🧪
*число * числоЧисло в общем типе. 3*4 → 12.✅
*строка * цел / цел * строкаПовтор строки N раз (N ≥ 0).🧪

4.2. Деление / — всегда вещественное

Осознанное решение Оператор / всегда даёт вещественный результат (F128), даже для двух целых: 7 / 2 → 3.5 (характеризация char_binary_div_integers_is_float). Это сознательный выбор в духе Python 3, устраняющий классическую ловушку «целочисленного деления по умолчанию» для учеников. Деление на ноль — ясная ошибка выполнения, не паника. ✅ 
вывод 7 / 2      | 3.5   (вещ, не 3)
вывод 20 / 5     | 4     (значение целое, но тип — вещ)
вывод 5 / 0      | ошибка выполнения: деление на ноль

Дополнительно для строк / перегружен: строка / цел режет строку на N примерно равных частей, строка / строка — разбивает по разделителю и возвращает пару (части, число_разбиений). 🧪

4.3. Целочисленное деление див

див — новый оператор-слово (лексема Token::IntDiv), возвращающий целое частное с усечением к нулю (как / для целых в Rust), только для целых операндов: 

вывод 7 див 2      | 3
вывод 10 див 3     | 3
вывод -7 див 2     | -3   (усечение к нулю, НЕ floor -4)
вывод 7 див -2     | -3
вывод 5 див 0      | ошибка выполнения: деление на ноль

На нецелых операндах — ясная ошибка «целочисленное деление только для целых». Характеризация: char_binary_intdiv_keyword, char_binary_intdiv_negative_truncates_toward_zero, char_binary_intdiv_by_zero_is_error. ✅

4.4. Остаток мод / %

мод (лексема Token::Percent, синоним %) — остаток от деления, только для целых. Реализация использует Rust-остаток %, который усекает частное к нулю; поэтому знак результата совпадает со знаком делимого: 

вывод 7 мод 3      | 1
вывод 10 мод 4     | 2
вывод 7 % 3        | 1
вывод -7 мод 2     | -1   (знак — от делимого)

4.5. Тождество див/мод

Инвариант Для всех целых a и b ≠ 0 выполняется (a див b) * b + (a мод b) == a (тест char_binary_intdiv_mod_identity на парах (7,2),(10,3),(20,5),(17,4),(100,7)). Оба оператора усекают к нулю согласованно.

4.6. Возведение в степень **

a ** b вычисляется в F128 через powf; результат — вещественное число (даже для целых основания и степени: 2 ** 3 → 8.0). Правоассоциативен на уровне грамматики (см. KITE 12). Отрицательное основание с дробной степенью и переполнение диагностируются только в режиме «ошибка при переполнении» (fo_e), который в интерпретаторе сейчас выключен (см. §10) — поэтому такие случаи дают inf/nan, а не ошибку. ✅ (тип результата — вещ)

5. Сравнения и равенство

ОператорСемантикаРезультат
=Структурное равенство значений (Value == Value).лог
<> / !=Отрицание равенства.лог
< > <= >=Упорядочение чисел, строк, символов.лог

Сравнимые пары (ops/predicates.rs): число↔число, строка↔строка (лексикографически), символ↔символ. Прочие сочетания — ошибка «несравнимые типы».

Шов точности сравнений Числа при </>/<=/>= сейчас приводятся к f64 и сравниваются через partial_cmp (ops/predicates.rs, шов [typesys-seam]). Для очень больших цел_128/нат_128 и вещ_128 это может терять точность. Равенство (=) — иное: оно структурное (Value == Value) и на числах сравнивает по представлению, то есть цел и вещ с равной величиной не считаются равными. Lossless-сравнение смешанных чисел — предмет адопции typesys.

Унарный не сначала приводит операнд к истинности, поэтому применим не только к лог: не 0 → да, не "" → да. Унарный минус на нат_* — ясная ошибка (беззнаковое число нельзя отрицать), ops/unary.rs.

7. Операторы над обёртками: ??, ?., ?

7.1. Значение по умолчанию ?? (null-coalescing)

a ?? b вычисляет a; правая часть вычисляется лениво, только если a «пусто»:

  • a — Option: Некоторое(v) → v; Ничего → значение b.
  • a — пусто (Null) → значение b.
  • любое другое a → само a (правая часть игнорируется).

evaluator/mod.rs, ветвь Expr::Coalesce. Правоассоциативен (см. KITE 12). ✅

7.2. Безопасная навигация ?.

объект?.поле и объект?.метод(...): если объект — пусто или Ничего, результат — пусто, без вычисления доступа/вызова. Иначе — обычный доступ к полю / вызов метода. evaluator/mod.rs (SafeField/SafeMethod). ✅

7.3. Проброс ошибки ? (ранний возврат)

Постфиксный выражение? десугарится парсером в вызов выражение.__propagate__() и реализует раннее завершение объемлющего алгоритма/ метода/лямбды (evaluator/method.rs → eval_propagate):

Значение слеваДействие
Успех(v) (Result::Ok)развернуть до v
Некоторое(v) (Option::Some)развернуть до v
Ошибка(e) (Result::Err)ранний возврат с Err(e)
Ничего / пусторанний возврат с Пусто
значение-ошибка (Value::Error)ранний возврат самого значения
иное (например 5?)ясная ошибка TypeMismatch: «Оператор '?' применим только к…»
Механизм раннего возврата Проброс реализован особым сигналом-ошибкой с полем propagate (error.rs), который перехватывается на границе вызова алгоритма/метода/лямбды и превращается в возврат несомого значения. Характеризация: char_propagate_unwraps_some, char_propagate_null_short_circuits_algorithm, char_propagate_on_plain_value_is_clear_error. ✅ Синтаксиса типа T!E для создания результатов на поверхности пока нет (см. открытые вопросы и будущий KITE о модели ошибок).

8. Операции над строками и коллекциями

Помимо чисел, арифметические операторы имеют перегрузки (все реализованы в MathOperators):

ВыражениеРезультат
"ab" + "cd""abcd" — конкатенация
"ababa" − "ba"удаление всех вхождений подстроки
"ab" * 3"ababab" — повтор
"abcdef" / 3массив из ~равных частей
"a,b,c" / ","пара (["a","b","c"], 2)
[1,2] + [3][1,2,3]
[1,2,3,2] − [2][1,3,2] (удаляет одно вхождение)
Строки и числа не складываются строка + число — ошибка несовместимости типов. Это, в частности, влияет на интерполяцию (§13.5): встраиваемые значения должны быть строками, иначе конкатенация не пройдёт.

9. Диапазоны, конвейер, композиция

9.1. Диапазоны .. / ..= с шагом

начало..конец (исключая конец) и начало..=конец (включая) дают значение Value::Range { start, end, inclusive, step }. Границы вычисляются как целые; необязательный шаг n задаёт шаг (по умолчанию 1). Шаг 0 — ошибка. Диапазоны без начала/конца пока не поддерживаются. evaluator/range.rs. ✅ 

нц для x в 1..10        | 1..9
нц для x в 1..=10       | 1..10
нц для x в 0..=100 шаг 2 | 0,2,4,…,100

9.2. Конвейер |>

x |> f и x |> f(a, b) подставляют вычисленное x первым аргументом вызова: f(x) и f(x, a, b) соответственно. Цепочки левоассоциативны и разворачиваются последовательно. Правая часть обязана быть вызовом функции/именем функции, иначе ошибка. evaluator/pipe.rs. ✅

9.3. Композиция >>

Разобрано, но не вычисляется Оператор композиции функций f >> g разбирается парсером, но в вычислителе для него нет ветви — вычисление даёт ошибку «не реализовано». 📋

10.2. Проверка типа выражение это Тип

Постфиксный это (после выражения) выполняет проверку типа и возвращает лог (ops/cast.rs → type_check). Распознаются цел(I64), вещ(F64), лит, лог, сим, таб и любой (последний — всегда истина). Несовпадение даёт нет, не левый операнд. ✅

Двойная роль это Лексема это служит и ссылкой на себя внутри метода, и постфиксной проверкой типа. Дизамбигуация — по позиции: постфиксная позиция после выражения = проверка типа.

11. Числовая модель и приведения

Числа представлены перечислением Number (shared/src/types/number.rs): знаковые I8…I128, беззнаковые U8…U128 и вещественные F32/F64/F128. F128 — расширенная точность, служит «универсальным вещественным» для всех делений, степеней, корней и тригонометрии.

11.1. Как комбинируются смешанные числовые типы

Правила из MathOperators::int_or_float (для + − *):

  • Оба операнда целые → операция целочисленная. Общий тип: знаковость = «знаковый, если хоть один знаковый»; ширина = максимум рангов операндов (цел_16 + цел_64 → цел_64).
  • Хотя бы один вещественный (или смешанный так, что целочисленная ветвь неприменима) → оба приводятся к F128, результат — F128.
  • / и ** — всегда через F128 (см. §4).
  • див и мод — только целые, результат в целочисленном типе операндов (сейчас реализованы пути I32/I64/U32/U64).
Рантайм ≠ движок типов Правило «общий тип по большему размеру/точности» из движка типов (result_of_binop, common_type, решётка расширения в shared/src/typesys/rules.rs) ещё не подключено к рантайм-операциям. Практический эффект: рантайм часто отдаёт F128 там, где движок типов вычислил бы более узкий тип. При адопции typesys расхождения будут устраняться осознанно, со ссылкой на характеризационные тесты.

11.2. Приведения при кастах

Явные приведения — см. §10. Скрытых сужений нет: их можно получить только явным как. Строку в число превращает только каст ("2.5" как вещ), арифметика строку и число не смешивает.

12. Переполнение

Все операции MathOperators принимают флаг fo_e («fail-on-overflow»). Интерпретатор вызывает их с fo_e = false (ops/binary.rs), поэтому текущее поведение таково:

  • Целые: при переполнении узкого типа результат автоматически расширяется до более широкого (вплоть до цел_128/нат_128). Если и он переполнен — ясная ошибка «Переполнение числа». Внутри узкого типа арифметика идёт через wrapping_*, но результат сразу проверяется на попадание в тип и при выходе — расширяется.
  • Вещественные: переполнение даёт inf/nan без ошибки (проверка на inf/nan активна только при fo_e = true).
Не финализировано Единая политика переполнения (ошибка / насыщение / wrap) языком пока не зафиксирована нормативно — это открытый вопрос (§15). Текущее поведение — «авторасширение целых + тихий inf для вещественных» — следует считать реализационной данностью, а не гарантией. 🧪

13.2. Значения по умолчанию

Переменная без инициализатора получает значение по умолчанию своего типа через shared::typesys::default_engine() (ops/defaults.rs): цел → 0, вещ → 0, лог → нет, лит → "" (пустая), сим → '\0' (NUL). Типы без естественного умолчания дают Undefined. Характеризация: char_default_*. ✅

14. Специальные формы выражений

14.1. Кортеж (a, b, …)

Скобочный список даёт Value::Tuple; каждый элемент вычисляется штатным вычислителем ((1+1, 2*3) → (2, 6)). Характеризация: char_tuple_literal_evaluates, …evaluates_elements. ✅

14.2. Литерал массива […]

Даёт Value::Array; каждый элемент вычисляется (evaluator/mod.rs → ArrayLiteral). Ранее не-литеральные элементы молча превращались в Undefined — дефект исправлен: [x, x+1, x*2] корректно вычисляет все элементы. Характеризация: char_array_literal_evaluates_nonliteral_elements, …of_literals_still_works. ✅ Литералы множества {…} и словаря {k: v} пока не разбираются — 📋.

14.3. If-выражение если … то … иначе …

Условное выражение: вычисляет условие, затем ровно одну ветвь; результат — её значение (evaluator/mod.rs → IfExpr). Условие приводится к истинности по §13. ✅

14.4. Match-выражение

Сопоставление с образцом в позиции выражения (evaluator/match.rs): значение сравнивается с ветвями, результат — значение первой подходящей. 🧪

14.5. Лямбды

Лямбда-выражение создаёт Value::Lambda, захватывая свободные переменные из окружения (по значению). Поддержана и краткая запись x => x + 1. Оператор ? в теле лямбды выполняет ранний возврат из самой лямбды. ✅

14.6. Интерполированные f-строки

f"…{выражение}…" лексируется на части и десугарится парсером в цепочку конкатенаций +: f"Привет, {имя}!" становится "Привет, " + имя + "!" (shared/src/parser/expr.rs).

Ограничение Поскольку десугаринг — это конкатенация +, а строка + число — ошибка (§8), встраиваемые выражения должны давать строку: для чисел требуется явное {n как лит}. Автоматической стрингификации встраиваемых значений пока нет. 🧪

16. Открытые вопросы

  • Политика переполнения (§12): язык должен нормативно выбрать ошибка / насыщение / wrap / авторасширение. Сейчас — авторасширение целых и тихий inf для вещественных.
  • Адопция typesys (§5, §11): подключить result_of_binop и lossless-сравнение смешанных чисел; каждое изменение поведения — со ссылкой на характеризационный тест.
  • как сим (§10): реализовать приведение число→символ.
  • Композиция >> (§9.3): добавить ветвь вычисления.
  • Стрингификация в f-строках (§14.6): автоматически превращать встраиваемые значения в строку.
  • Модель ошибок и T!E: поверхностный синтаксис для создания результатов/ошибок — предмет отдельного KITE; сейчас ? работает, но конструкторов Успех/Ошибка на поверхности нет.
