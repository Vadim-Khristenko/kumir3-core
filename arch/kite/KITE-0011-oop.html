1. Область применения

Документ определяет объектную модель Kumir 3: виды пользовательских типов (класс, структура, интерфейс, типаж, перечисление), наследование и полиморфизм, состав членов типа, видимость, жизненный цикл объекта, обобщённые типы и перегрузку операторов.

Документ не решает следующих вопросов:

  • форма записи объявлений и вызовов — KITE 12;
  • набор типов языка и метки их стабильности — KITE 2;
  • отношения между типами, проверка присваиваний, значения по умолчанию — KITE 10;
  • окружения и кадры вызова — KITE 4;
  • модель ошибок — KITE 14;
  • разрешение имён членов модуля — KITE 15.

2. Термины и обозначения

  • Тип-носитель — класс, структура, интерфейс, типаж или перечисление.
  • Член типа — поле, метод, конструктор или деструктор. Каждый член имеет видимость и набор модификаторов.
  • Объект — экземпляр класса или структуры: запись полей, связанная со своим типом.
  • Иерархия — цепочка типов от типа объекта вверх по предкам.
  • Разрешение метода — выбор реализации метода по иерархии типа объекта.
  • Реестр типов — часть среды исполнения, хранящая связь объект → тип и отношение наследования (KITE 10).

Метки стабильности применяются в значении KITE 0 § 5, ключевые слова требований — в значении KITE 0 § 2.2.

3. Нормативные правила

3.1. Модель типов

Член типа — поле, метод, конструктор или деструктор; каждый член имеет видимость и модификаторы.

3.2. Наследование и полиморфизм

  • Наследование: расширяет задаёт единственного предка, реализует — список интерфейсов.
  • Разрешение методов по иерархии: поиск метода идёт от типа объекта вверх по предкам; выигрывает первый найденный. стабильно
  • Виртуальная диспетчеризация: вызов разрешается по фактическому типу объекта, переопределение выигрывает; финал запрещает переопределение, абстрактный требует реализации в неабстрактном потомке. стабильно
  • Вызов предка: предок.метод(…) вызывает реализацию родителя в обход переопределения; поиск начинается с родителя того класса, где определён текущий метод. стабильно
  • Абстрактные классы: создание экземпляра абстрактного класса ДОЛЖНО давать ошибку. стабильно

Лексема предок ДОЛЖНА применяться исключительно в форме предок.метод(…). Голый предок — как значение, как приёмник поля или как аргумент — ДОЛЖЕН давать ошибку выполнения: «'предок' можно использовать только как вызов метода предка: 'предок.метод(...)' — самостоятельным значением он не является». Объект Kumir 3 — единая плоская запись полей, и отдельного объекта-предка модель не содержит. Форма предок(…) для цепочки конструкторов — предложено (§ 3.4). Грамматика этих форм — KITE 12.

3.3. Интерфейсы и типажи

  • Интерфейс — набор сигнатур; тип, объявивший реализует, ДОЛЖЕН предоставить их реализации.
  • Типаж (свойство) — набор сигнатур с дефолтными реализациями методов и супертипажами.
  • Реализация: реализация Типаж для Тип привязывает методы к типу.
  • Диспетчеризация через impl-блоки: метод из реализация [Типаж] для Тип ищется по типу и его предкам после методов класса. стабильно
  • Дефолтные реализации типажа и проверка соответствия интерфейсу. предложено
  • Проверка реализации через реестр типов: номинальный подтип (KITE 10). экспериментально

Порядок построения объекта:

  1. поля получают значения по умолчанию или значения явных инициализаторов;
  2. аргументы конструктора вычисляются в кадре вызывающего (KITE 4);
  3. создаётся кадр конструктора с это;
  4. исполняется тело конструктора;
  5. значением выражения новый становится объект из это.

3.5. Обобщённые типы

  • Параметры типа объявляются на классах, методах, интерфейсах и типажах.
  • Ограничение где задаёт требования к параметру: реализация типажа, подтип и подобные.
  • Обобщённый тип представляется именем и списком аргументов типа; совместимость проверяет движок типов ковариантно по аргументам (KITE 10).
  • Аргументы типа стираются при исполнении; проверка типов выполняется на границах обобщённого кода. предложено

3.6. Перегрузка операторов

  • Оператор выражается типажом-оператором (например Сложение, Сравнение): выражение a + b разворачивается в вызов метода типажа.
  • Тип результата операции определяет движок типов (KITE 10) либо сигнатура метода типажа.
  • Перегрузка операторов позволяет типам дробь, комплекс, вектор вести себя как числа (KITE 2 § 3.10). предложено

3.7. Связь с движком типов

Объектная модель опирается на движок типов (KITE 10):

  • Номинальный подтип — наследование и реализация интерфейсов разрешаются через реестр типов.
  • Идентичность объекта — объект связан со своим типом стабильным идентификатором типа, а не набором полей; на этой связи основана диспетчеризация (§ 3.2).
  • Проверка присваиваний и параметров методов — правилами совместимости движка.
  • Типы полей и значения по умолчанию — правилом значения по умолчанию.
  • Перегрузка операторов — типизацией бинарных операций.

5. Совместимость

КуМир 2 не содержит объявлений классов, структур, интерфейсов и типажей, поэтому программы КуМир 2 правилами этого документа не затрагиваются. Режим совместимости нормирован в KITE 6.

Возможность с меткой стабильно подчиняется гарантиям KITE 0 § 5.5. Для возможностей с прочими метками гарантии не действуют, и программа НЕ ДОЛЖНА на них полагаться.

Относительно версии 0.1.0 настоящего документа правила и метки стабильности не изменены; изменены состав и нумерация разделов. Прежние разделы 2–8 соответствуют пунктам § 3.1–§ 3.7.
